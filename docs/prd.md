# PRD: code-puppet

## 問題定義

YouTube等のライブ配信において、Vtuberスタイルのアバターを使って顔をカメラに映さず配信したいというニーズがある。既存のソリューション（Live2D、VTube Studio 等）は外部エンジンへの依存、GUI操作、ライセンス費用が伴い、エンジニアがコードベースで完全に制御・カスタマイズすることが難しい。

**解決したい課題**: 完全コード駆動・ゼロ依存コストで、独自デザインのアバターをリアルタイムに制御できるWebアプリを自前で構築する。

---

## ユーザーストーリー

| #   | ストーリー                                                                                           | 受け入れ基準                                              |
| --- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 1   | 配信者として、カメラ映像から顔のトラッキングをリアルタイムに行い、アバターを自分の動きに連動させたい | 頭の傾き・向き・瞬き・口の開閉がアバターに反映される      |
| 2   | 配信者として、背景透過されたアバターをOBSでキャプチャしてゲーム映像と合成したい                      | Webブラウザ上のキャンバスが透過背景でレンダリングされる   |
| 3   | エンジニアとして、アバターのデザイン変更やパーツ追加をコードだけで完結させたい                       | テクスチャPNGを差し替えてコードを修正するだけで反映される |
| 4   | エンジニアとして、将来的に全身トラッキングや追加パーツ（触角・翼 等）に対応できる拡張性を持ちたい    | `TrackingFrame` と `AvatarPartConfig` の構造で拡張できる  |

---

## 成功指標

- ブラウザ上で **30fps以上** のレンダリングを維持できる（M1 MacBook Air基準）
- 顔トラッキングの **遅延が視覚的に許容範囲内**（体感100ms未満）
- 初期アバターパーツ（体・頭・目×2・口・腕×2・尻尾）が **すべて正しく描画・連動** される
- OBSのブラウザソースで **背景透過** が正しく動作する

---

## スコープ外

- GUI設定画面・スライダー操作によるパラメータ調整
- 全身トラッキング（手・ポーズ）―― 将来拡張として設計は考慮するが初期リリースは対象外
- スプライトシートによるテクスチャ管理（初期はPNG個別読み込みで対応）
- サーバーサイド処理・ユーザー認証・データ永続化
- モバイルブラウザ対応
- Windows / Linux 環境でのサポート（開発環境はM1 Mac固定）
