# ADR-003: 背景は透過ではなくマゼンタのクロマキーにする

- **ステータス**: 承認済み
- **決定日**: 2026-10-07（実装は 2026-04-10 の 28bd5db・865a3fe）

---

## コンテキスト

当初の要件と設計（PRD、Design Doc、[ADR-001](./ADR-001-use-pixijs-v8.md)）は、キャンバスを `backgroundAlpha: 0` で透過させ、OBS のブラウザソースでそのまま合成する前提だった。

2026-04-10 に、OBS のクロマキーフィルタで合成できるよう、実装を不透明な単色背景へ切り替えた。最初はグリーン（`#00ff00`）にしたが、アバターの葉っぱ（緑）まで抜けてしまったため、同日マゼンタ（`#ff00ff`）に変更した。

その後も文書は背景透過のまま残り、実装と食い違っていた。透過での合成をやめた経緯そのものは、コミットに記録が残っていない。

---

## 決定

背景は **不透明なマゼンタ（`#ff00ff`）の単色** とし、OBS 側の **クロマキーフィルタ** で抜いて合成する。

- `RendererImpl.init()`: `backgroundAlpha: 1`、`background: 0xff00ff`
- `index.html`: `body { background: #ff00ff }`

背景透過は要件から外す。ADR-001 の PixiJS v8 採用はそのまま有効で、変わるのは同 ADR が挙げていた背景透過の要件だけである。

---

## 結果

コードから確認できるもの以外は、クロマキー一般の性質から書いた見込みで、このプロジェクトでの実測ではない（該当する項目に「見込み」と記した）。

### ポジティブ

- 見込み: 取り込み方法を選ばない。ブラウザソースに限らず、ウィンドウキャプチャや画面キャプチャでも合成できるはずである
- 通常のブラウザで開いたときにも、配信に載る範囲が目で見て分かる

### ネガティブ

- アバターにマゼンタ系の色を使えない。使うとその部分が抜ける
- 見込み: パーツの輪郭（アンチエイリアスの半透明部分）にマゼンタがにじむ可能性があり、その場合は OBS 側でフィルタの調整が要る
- 見込み: 半透明の表現（影・ぼかし等）はきれいに合成できない可能性がある
- 背景色が `RendererImpl.ts` と `index.html` の 2 箇所に書かれており、変えるときは両方を揃える必要がある

---

## 検討した代替案

| 案                             | 概要                                   | 棄却理由                                                       |
| ------------------------------ | -------------------------------------- | -------------------------------------------------------------- |
| 背景透過（`backgroundAlpha: 0`）| 当初の設計。OBS ブラウザソースで直接合成 | 理由は記録が残っておらず不明。2026-10-07 にユーザーがクロマキーを正と決めた |
| グリーンバック（`#00ff00`）    | クロマキーで最も一般的な色             | 葉っぱ（緑）が一緒に抜けてしまう                               |
