# ADR-002: MediaPipe と PixiJS の非同期分離（latestFrame バッファ方式）

- **ステータス**: 承認済み
- **決定日**: 2026-03-29

---

## コンテキスト

MediaPipe の FaceLandmarker はカメラフレームを非同期で処理し、コールバックでトラッキング結果を返す。一方、PixiJS は `requestAnimationFrame`（rAF）を使ってレンダリングループを回す。

この2つの処理サイクルは **独立した頻度とタイミングで動作** するため、MediaPipeのコールバック内で直接 PixiJS を更新すると以下の問題が生じる。

- コールバックが rAF のタイミングとずれてフレームが2重更新・スキップが起きる
- コールバックが遅延した場合にレンダリングループがブロックされる
- MediaPipe と PixiJS の結合度が高くなりテストが困難になる

---

## 決定

MediaPipe のコールバックは **`latestFrame` バッファに結果を書き込むだけ** にとどめ、PixiJS Ticker が **毎フレームそのバッファをポーリング** してレンダリングに利用する方式を採用する。

```
MediaPipe callback → latestFrame バッファ（書き込み）
                                ↓
PixiJS Ticker（rAF） → latestFrame バッファ（読み取り） → Renderer 更新
```

---

## 結果

### ポジティブ

- レンダリングループが MediaPipe の処理遅延に影響されず安定する
- MediaPipe・Mapper・Renderer の3層が疎結合になり、各層を独立してテスト・差し替えできる
- コードが単純: `Tracker` は「バッファを更新するだけ」、`main.ts` の Ticker は「バッファを読むだけ」

### ネガティブ

- MediaPipe が 1フレーム分の処理を完了する前に rAF が走ると、直前のフレームデータを再利用する（最大 1フレーム分の遅延）
- `latestFrame` はミュータブルな共有状態であるため、型安全性に注意が必要（TypeScript で `null` チェックを徹底する）

---

## 検討した代替案

| 案                           | 概要                                                          | 棄却理由                                                                                       |
| ---------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| コールバック直接レンダリング | MediaPipe コールバック内で直接 `renderer.updatePart()` を呼ぶ | rAFと無関係なタイミングで描画が走り、フレームレートが不安定になる。MediaPipeとRendererが密結合 |
| RxJS / Observable            | MediaPipeの出力をストリームとして流す                         | 依存ライブラリが増える割にメリットが薄い。シンプルさを優先                                     |
| SharedArrayBuffer + Worker   | MediaPipeをWeb Workerで分離                                   | COOP/COEPヘッダ設定が必要でインフラ要件が増える。現時点では過剰                                |
